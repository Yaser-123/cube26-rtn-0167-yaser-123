Inspection API

Send photos of a returned item and the SKU that was ordered. You get back the decision and the evidence for it.

Endpoint

POST /api/v1/inspect
Header:  X-API-Key: <your key>
Body:    multipart/form-data

Form fields

FieldRequiredDescription
imagesyes1–3 photos (JPEG, PNG, WebP, GIF), each under 10 MB. Repeat the field for each photo.
skuyesThe ordered SKU, e.g. SKU-BOTTLE-750.
partsnoExpected parts, separated by ;. Defaults to the catalogue entry, and required for SKUs not in the catalogue.
unit_idnoYour ID for this unit. Generated if omitted.
order_id, asinnoStored with the record.

Example

curl -X POST /api/v1/inspect \
  -H "X-API-Key: YOUR_KEY" \
  -F "sku=SKU-BOTTLE-750" \
  -F "images=@front.jpg" \
  -F "images=@side.jpg"
import requests

with open("front.jpg", "rb") as front, open("side.jpg", "rb") as side:
    r = requests.post(
        "/api/v1/inspect",
        headers={"X-API-Key": "YOUR_KEY"},
        data={"sku": "SKU-BOTTLE-750"},
        files=[("images", front), ("images", side)],
    )
r.raise_for_status()
record = r.json()
print(record["outcome"], [(c["check_key"], c["verdict"]) for c in record["checks"]])

Decisions

  • restock: New or Like New, complete
  • refurbish: light wear, or a sound item missing a part
  • liquidate: heavy wear
  • dispose: broken or heavily damaged
  • pending_review: wrong item, or something couldn't be verified from the photos

Errors and limits

  • 401: missing or wrong API key
  • 400 / 413 / 415: wrong number of images, too large, or not an image
  • 429: too many requests; wait for the Retry-After seconds
  • If the vision model is down or the daily budget is used up, you still get a record back, with pending_review and the reason in each check. Nothing is lost.

Each key belongs to one client account and can only see that account's records. Ask the operator for a key.
